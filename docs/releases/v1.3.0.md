# Startup Manager v1.3.0

本次更新解决“每次开关都要等很久”的问题，并为受保护项增加批量管理。

## 开关与扫描速度

- 开关不再在修改前后各做一次全量系统扫描。修改前复用最近一次扫描（最多 2 分钟）
  解析目标，修改后把已验证的结果直接更新到界面快照；只有“从备份重新启用”等
  会生成新条目的少数情况才重新扫描。
- 提权助手（UAC）只扫描目标所属的来源（例如只读服务或只读计划任务），不再扫描
  整台机器；主界面在提权操作后也只重新读取受影响的来源。
- 监视器实测：真实运行的应用中，注册表启动项从点击到界面更新约 **230-330 毫秒**
  （开关各测一次）；修改前约为数秒。
- 全量扫描本身也更快：
  - MSIX 应用包改用 `InstalledPath` 读取安装位置，避免每个包激活
    `StorageFolder` 的昂贵开销（本机 2.2-3.1 秒 → 0.14-0.5 秒）。
  - 只解析含有 `startupTask` 声明的清单文件。
  - 服务扫描只为自动启动的服务读取延迟启动标志，并移除未使用的描述读取。
  - 发布者版本信息增加进程内缓存。
  - 五个扫描来源并行读取（任务计划程序 COM、服务管理器、注册表、启动文件夹、
    应用包），全量扫描约 2.3-3.2 秒（原 4.5-8.8 秒）。

## 批量管理受保护项

- 工具栏新增“允许管理…”和“恢复保护…”：对当前分类（可配合搜索/筛选）中的
  工具保护项一次解锁或重新锁定，不再需要逐项打开详情。
- 确认窗口展示数量、不可解锁的 Windows 策略项数量，并明确说明不会改变启动状态。
- 解锁后可直接用“全部禁用…”批量关闭；批量结果逐项报告，策略锁定项会被跳过并
  计入失败数量。
- 单项的“允许管理…”/“恢复工具保护”和恢复中心行为保持不变。

## 安全与一致性

- 每次实际写入仍先备份、后应用、再重新读取系统状态验证；失败自动回滚。
- 修改仍会重新读取目标项的实时系统状态；缓存只用于定位目标与权限判断，且
  2 分钟后强制重新扫描。
- 提权操作在独立的提权进程中重新扫描并重新校验保护规则，主机不会绕过。
- Windows 策略限制、安全检查失败、ACL 拒绝仍不可覆盖。

## 验证

- Release 候选：**230 项测试通过、1 项权限相关跳过**（224 Core + 6 App）。
- Web UI 演示模式 37 项检查通过（含新增批量解锁/恢复流程）。
- 原生宿主真实开关：注册表启动项从点击到界面更新 **230-330 毫秒**。
- 直接运行发布版提权助手（非提权直跑临时测试项，含进程启动、按来源扫描、备份、
  写入和验证）：关闭 **414 毫秒**、开启 **562 毫秒**，启动批准值按预期切换。
- 测试用的注册表值、批准值、备份与 IPC 文件均已清理。
- 仍未自动化真实的安全桌面 UAC 提示；普通服务/计划任务的提权切换仍需人工验收。

需要 Windows 11 x64 和 WebView2 Runtime；无需另装 .NET。附 SHA-256 校验文件。
